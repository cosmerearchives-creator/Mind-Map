# Larger workspaces and shared image storage

There is no fixed total workspace cap. Imports and writes check estimated free device storage, allowing approximately twice the new encoded bytes for transaction overhead. Low-space warnings appear below 10% headroom or 32 MiB. Unknown estimates allow writes and rely on atomic IndexedDB quota errors. Paste measures unique image content instead of counting a copied image repeatedly. Selection clipboard text is limited to 64 MiB, Milanote HTML/custom text to 64 MiB, recovered Milanote media to 128 MiB per paste, and an individual downloaded image to 8 MiB and 64 million decoded pixels. Memory and available IndexedDB storage remain practical device limits.

The live editing model uses compact session image references backed by an original-byte pool. Export and sync resolve those references to the existing portable formats. Persistence extracts each unique data URL into an asset-<SHA256> record in the existing documents store. Board documents, local recoveries and automatic sync metadata contain references; each write includes needed assets and documents in a single transaction. Writes serialize and stale pending local saves are discarded. A load verifies referenced hashes before exposing data; a damaged stored asset blocks editing instead of overwriting the saved workspace with starter content. Old inline records migrate lazily on their next successful save.

New backups and image-containing selection payloads use silverlight-assets-v1 bundles. Every reference must have matching image bytes. Legacy inline JSON remains accepted. No lossy image conversion is introduced. Undo stores shared image references in memory and retains images needed by existing undo/redo entries.

Cloud transfers retain legacy small text-only snapshots. Other snapshots are packed into a document and unique image objects, divided into 1 Mi-character parts. Each part is checked by SHA256 and uploaded as an immutable silverlight-part-v2 object; a silverlight-transfer-v2 manifest is uploaded last. Drive app properties keep parts out of the manual snapshot list and automatic workspace groups. Existing parts with matching hashes are reused, including across different snapshots. Download lists permitted IDs, validates part count, lengths, total bytes, part hashes, manifest checksum, asset hashes, and the original snapshot revision before applying. Interrupted uploads may leave reusable orphan parts but no completed snapshot manifest. No cloud files are automatically deleted.

Both apps must be upgraded before using v2 cloud transfers or bundled backups. Old inline snapshots still verify; older apps reject the new formats. Native upload/download guards are 256 MiB per individual request, while multipart workspaces use small parts and can exceed 256 MiB in total. The transfer decoder retains a 16,384-part protocol safeguard. Current OAuth, account matching, appDataFolder permissions, conflict preservation and atomic local recovery remain in place.

Checks: node tests/validate.cjs includes assets-transfer.cjs (>64 MiB fixture, duplicate assets, checksums, interruption and part reuse). Browser checks include asset-storage-delete.cjs, drive-transfer.cjs, automatic-sync.cjs and the existing clipboard/selection suites. These simulate transport and device storage; real signed-in Drive transfers and physical Android memory limits still require device testing.

Large Boards mount only visible Stickies and wire groups, with viewport overscan and active-editor retention. Spatial indexes and cached Collection layout reduce repeated scans. Drag frames update moving nodes and affected wire groups. IndexedDB now stores a Board manifest and individual Board records; unchanged Boards and existing assets are not rewritten. Legacy inline and asset-only records remain readable. Background workers prepare hashes, snapshots, sync operations and storage records, with an idle fallback where workers are unavailable. Display thumbnails use bounded caches; original image bytes remain intact. See performance.md for measurements and limitations.

Saved Board manifests include small home-screen summaries. Original image sizes are recorded separately from bytes; startup checks referenced asset keys without loading all originals. Board JSON records remain compact until accessed; navigation releases parsed models for other Boards. The original-image cache is bounded at 32 MiB of encoded strings, and single originals over 16 MiB bypass that cache. Display thumbnails and worker transfer pools have separate budgets. Legacy records without summaries/sizes are accepted and gain metadata on subsequent saves. Images are hash-verified when loaded; missing asset keys block workspace loading, and corrupt image bytes are retained for recovery rather than overwritten.

Ordinary saves preserve disk references without materializing every original. Export, selection copy, and sync hydrate the required data and verify originals, including unopened Boards. These operations still need temporary memory for the complete exported/transferred data; this update does not make them streaming or unlimited. Snapshot revisions below the legacy threshold remain unchanged. Above it, a compact document plus sorted image content hashes protects the whole workspace without building a huge canonical image string. Older apps cannot verify these larger snapshots and must be updated before using them.

Additional checks: workspace-capacity.cjs verifies a 272 MiB unique-image workspace and quota decisions; set TEST_LARGE_TRANSFER=1 to include its simulated multipart round trip. on-demand-storage.cjs verifies 30 unopened Boards, original-image demand loading, model release, stored edits, quota rollback, complete backup hydration, and missing-image startup protection.
