# 0.18.1 conflict resolution and Android assets

Inspection found a shared silent return in `resolveBoard` whenever background sync held `running`. The old automatic-sync test resolved only an idle conflict and did not cover this path. The repair queues a single explicit choice, shows waiting/saving status, prevents another poll from overtaking it, and restores controls with a persistent error after failure. A bounded wait reports an unresponsive background operation. Changed versions invalidate the reviewed choice instead of applying an obsolete version index.

Resolution still retains alternative content as separate Boards. Recovery now includes the complete pre-resolution sync metadata (all competing versions), alongside the previous workspace. These recovery data, the replacement workspace and new sync metadata are committed in the same IndexedDB transaction. A failed transaction must leave all three unchanged. Tests use isolated synthetic workspaces and mocked Drive accounts; no installed workspace or real Drive copies are touched.

`conflict-resolution-ui.cjs` exercises each of Use version 1, Use version 2 and Keep all on desktop and mobile viewports. Each case deliberately holds background sync, clicks once, checks visible waiting/disabled controls, injects a storage failure, checks unchanged conflict metadata, retries and checks both versions plus recovery metadata. It also checks decoded HTML preview text. `automatic-sync.cjs` verifies actual IndexedDB recovery includes both full pre-resolution versions, in addition to its existing two-device propagation, atomic abort/retry, image and offline tests.

Android's existing visible label is already Archives of Arcanum. The package remains `com.cosmerearchives.silverlight`; signing settings and required certificate fingerprint are unchanged. `UpdateAssetTest` exercises modern-only, legacy-only, both names in legacy-first order, desktop-only, malformed and untrusted asset cases in the Android emulator workflow. The APK build verifies the final package, version, label, signing certificate and every shared asset. The release publishes the two APK names only after a byte-for-byte comparison. Windows and Android remain gated on successful builds of the same current main commit.

Local shared validation and targeted synthetic browser checks are run before pushing. Native Android instrumentation and Windows updater/build checks run in GitHub Actions (this computer has no Android Java toolchain or .NET SDK). Actual upgrade installation on a user's existing phone is not simulated by a mobile browser viewport; package/certificate/version and asset checks protect compatibility without accessing real user data.
