# Windows Google authorization

The source configuration windows/google-oauth-client.json contains the public Desktop OAuth ID 854143772698-9naba6nl7itjhinav1abu32kbnrd0kj1.apps.googleusercontent.com. The existing client is named Silverlight Windows in project silverlight-512321 (external console branding may retain the old name), shared with Android. Google requires this Desktop client’s client_secret field even with PKCE. On October 24, 2026 the owner explicitly authorized shipping that installed-app client value as public configuration. GitHub Actions injects it from SILVERLIGHT_DESKTOP_CLIENT_VALUE into the packaged configuration as desktop_client_value; the value is absent from committed source and logs. It is not a confidential server credential and cannot authorize access to a user’s data without that user’s Google grant. Existing installed configuration is read only as a fallback; no config, dataset, local workspace or old cloud copy is migrated/deleted. A cached refresh credential is used only with its matching client ID.

Connect Google opens the system browser using S256 PKCE, random state and a random loopback port on 127.0.0.1. The only requested scope is https://www.googleapis.com/auth/drive.appdata. Access tokens remain in native memory. Refresh credentials are encrypted with Windows CurrentUser DPAPI and atomically replaced in %LOCALAPPDATA%/Silverlight/google-drive-session.bin. They are bound to that Windows user/machine and are not portable backups. Refresh runs before expiry and after restart; rotated refresh tokens are saved. Scope denial or revocation requires reconnect; background sync does not launch consent.

Sign out on this PC pauses live sync before deleting its credential. It preserves all pending local edits, causal history, account/workspace selection and cloud copies; it does not revoke other PCs. Connect Google again with the same account, then resume live sync. Account mismatches remain blocked by native and JS checks.

Production configuration inspected on October 24, 2026: client type Desktop, project audience External, publishing status In production, and Google Drive API Enabled. The owner approved adding the existing appdata scope to the consent configuration, and Google confirmed it saved. This scope is non-sensitive and accesses only the app's hidden Drive data. See https://developers.google.com/identity/protocols/oauth2/native-app and https://developers.google.com/workspace/drive/api/guides/appdata.

Validation: tests/auth/Auth.Tests.csproj drives the actual native class against fake HTTPS endpoints, exercising the real loopback listener, wrong-state rejection, PKCE verifier, no-secret exchange, DPAPI encryption/decryption, restart refresh, refresh rotation, sign-out, legacy config, revoked grants and missing scope. An isolated real-Google test also passed on October 24, 2026: browser consent/loopback/PKCE, DPAPI storage, restart refresh with the same account and local sign-out. It used a disposable profile and did not read/upload BOARD data. A second physical PC and the affected original workspace remain owner acceptance checks.

Install over the existing app without uninstalling or clearing WebView2/app data. On the existing PC, retain the original local workspace and let Pending finish. On a new PC, Connect Google once, then join the existing live workspace; do not create an unrelated group or restore an older cloud copy over unsynced local edits.

Release gates: tests/check-google-desktop-config.ps1 submits a deliberately invalid code to Google using installed-app metadata, requiring invalid_grant rather than a missing-client-setting error. CI injects metadata before this gate, then builds only after shared, native and browser regressions pass. For a manual isolated real-account check, run the auth test executable with --real-google CONFIG_PATH AUTHORIZATION_URL_OUTPUT and open the written URL in a browser on the same machine; the test deletes its own temporary credential and leaves existing Archives of Arcanum data untouched.
