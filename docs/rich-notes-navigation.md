# Rich notes, navigation and Unsorted Library

Note Stickies have an inline pencil editor and an expanded editor. Both provide font family, size, text and highlight color, bold, italic, underline, strike, headings, lists, Tab/Shift+Tab indentation, alignment, web links and undo/redo. Save commits the document; Cancel keeps the previous note. The expanded inline editor leaves the transformed canvas while open.

Plain legacy notes are displayed as escaped text without changing storage. Explicitly editing and saving writes `silverlight-rich-v1:` followed by sanitized HTML to the existing `body` property. Keeping the document in one property prevents text and formatting from merging independently. Existing snapshot and property-register formats are unchanged. Update both devices: an older app preserves the string but will display the serialized markup instead of formatting. HTML is sanitized again when displayed. Script, embedded-object and unsafe link content are removed; pasted images belong in the Unsorted Library rather than the text document.

The @ key or @ Board toolbar button opens a searchable existing-Board selector. Choose the Board view or a named Location Pin in that Board. Links use stable Board and pin IDs. Following a link records the previous view for Back; pin navigation centers the pin using the destination's current zoom. Missing destinations show a message. HTTP/HTTPS links use same-window navigation intercepted by the existing Windows shell and Android ACTION_VIEW handlers to open the system browser.

Board shortcut creates a reference without creating or renaming its target. Edit its destination Board/pin independently. Deleting a shortcut deletes only that Sticky. Deleting its target leaves a detectable missing destination. Nested Board and shortcut title position can be Inside, Below image/icon, or Hidden; changing it preserves background art and overlay settings. Empty shortcuts use the same reserved header/frame layout as nested Boards.

Double-click/tap blank canvas, then select Location Pin. The pin starts at that board-space point, remains movable using normal Sticky gestures, and can be renamed through its menu. Link destination selection lists pins by name.

Unsorted Library belongs to each Board. Ctrl+V/system Paste while the canvas is active, or the explicit Paste button, collects clipboard images, formatted text or URLs. Clicking alone never reads the clipboard. Paste inside an editor goes to that editor. Clipboard images retain their original bytes and alpha; the app does not flatten or JPEG-reencode them. Place or drag a library item to the canvas; the placement uses the current board-space transform and removes the library entry. Library contents persist with the Board in local storage, exports and Drive snapshots. Concurrent library edits conservatively retain Board conflict versions instead of losing either set of ideas. Explicit clipboard reads depend on WebView/platform permission; Ctrl+V/system Paste remains the fallback.

Backup import remaps colliding Board IDs together with nested, shortcut and rich-link targets. Imported Sticky/connection/pin IDs remain stable within their new Board namespace, preserving Collection membership, connections and pin targets. Unknown saved fields, background art and Unsorted content are retained.

Viewing/resizing clips overflowing Sticky content without scrollbars or deleting content. Header space reserves the fixed top-right menu and truncates a long header title. The connection and corner resize controls remain outside clipped content. Existing 120×80 minimum frames and Collection constraints remain in effect. Editing surfaces can scroll to expose the complete document.

Validation: `node tests/validate.cjs` includes rich document/library/shortcut/pin snapshot and property merge checks. Browser suites `rich-notes.cjs`, `canvas-editing.cjs`, `sticky-interactions.cjs`, `automatic-sync.cjs` and `drive-transfer.cjs` cover desktop/touch gestures, formatting, legacy cancellation, @ insertion, pin centering/Back, shortcut title placement, sanitized paste/place, persistence and two-device sync/restore regressions. Native packaging is verified by the Android and Windows release workflows. Actual system-browser launches, Android clipboard permissions, IME/keyboard behavior and upgrades over physical-device installations require device checks; browser simulation does not establish those results.
